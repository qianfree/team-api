# Phase 1 实施计划：JS 异步任务插件（引擎跑通 + 最小任务闭环）

## Context

依据已定稿的 [docs/design/JS异步任务插件设计方案-v1.md](D:/github/team-api/docs/design/JS异步任务插件设计方案-v1.md)（四项决策已拍板：与 Go 插件并存、新增 JS 渠道类型、Go adaptor 保留兜底、plugin:upload/manage 两权分立）。Phase 1 目标：**goja+esbuild 引擎基座、契约最小集、上传/激活/启停、/pjs 分发器、任务提交+查询闭环**。验收标准：golden 插件（suno 式）+ httptest mock 上游端到端跑通——上传→激活→路由生效→提交任务→落库→轮询→查询渲染。

计费在 Phase 1 走模型级默认价（`{"base":1.0}`，与现有 Go adaptor suno 同款）；usageSchema/表达式对接、产物转存、config[]、前端 UI、native vendor 路径（裸 `/suno/...`）+ 404 兜底均不在本阶段。

## 探索结论（关键复用点）

- 任务主链**全部复用不改**：`relay/handler/task_handler.go:101 HandleTaskSubmit`（选渠道→预扣→adaptor 13 方法→落库 `tsk_model_tasks`）与 `internal/logic/task/async_polling.go pollSingleTask`（按 Platform 分组→`FetchTask`→`ParseTaskResult`→CAS→结算）。JS 桥只需实现 `TaskAdaptor` 接口注册进 `relay/taskchannel/registry.go`
- 注册机制：`taskchannel.Register(ProviderType, factory)` + `task_handler.go:22-29` 空白导入
- 渠道信息经 `RelayInfo.ChannelMeta`（`relay/common/relay_info.go:16`），settings JSONB → `ChannelSettings` 结构体（:113）——需加一个 `PluginKey` 字段
- 轮询侧 `FetchTask(ctx, baseURL, apiKey, taskData)` 不带渠道信息，taskData 由 `async_polling.go:462-466` 组装 `{task_id, use_proxy, model}`——加一行 `"platform"` 传递插件标识
- relay 鉴权链：`middleware.ApiMaintenance, ResourceGuard, MaintenanceMode, ApiKeyAuth, RelayBodyLimit, ContentFilter`（cmd.go:563）
- 管理端 API 模式：`api/admin/v1/plugin.go`(g.Meta) → controller → service → `internal/logic/admin/plugin.go`；权限点加在 `internal/logic/admin/permission.go:17 predefinedPermissionGroups` + `internal/middleware/rbac.go:22 adminPermissionRules`
- 表：goose 迁移（`migrations/NNNNNN_*.sql` + embed）→ `make dao` 生成；日志 helper `internal/logic/task/task.go:235 LogInfo/LogError`（tsk_task_logs）
- 上游 HTTP：`relay/common/http_client.go NewPooledClient`；新依赖仅动根 go.mod（relaykit 子模块保持零依赖，go 1.25.8）

## 实施步骤

### 1. 依赖与常量
- `go get github.com/dop251/goja github.com/evanw/esbuild`（均纯 Go 无 CGo）
- `relay/constant/provider.go`：`ProviderJSTask ProviderType = 43`（42 后空闲；32/33 永久保留不复用）
- `relay/common/relay_info.go` `ChannelSettings` 加 `PluginKey string \`json:"plugin_key"\``

### 2. M0 引擎基座 `internal/jsplugin/`
- `engine.go`：`Engine`/`Instance` 接口 + goja 实现。esbuild `api.Build(bundle, format=iife, globalName="__PLG__", write:false)` 编译；实例 = `goja.Runtime` 执行 bundle 后取导出对象；`Call(hook string, args json.RawMessage) (json.RawMessage, error)` 走 JSON 边界；`time.AfterFunc → vm.Interrupt` 硬超时（默认 5s）；panic 恢复 + 实例重建计数；每实例互斥串行，池按 plugin_key（并发闸默认 8）
- `hostfunc.go`：注入 `utils.fetch`（限额：≤4 次/调用、15s/次、30s/批、1MiB/响应；host ∈ 渠道 baseUrl host ∪ manifest.allowedHosts；不跟随重定向；用 `NewPooledClient`）、`utils.log`（g.Log + 可选任务日志回调）、`utils.now`
- `observe.go`：hook 调用记录（插件 key/钩子/入参摘要/返回摘要/耗时/失败字段）→ `g.Log` + `task.LogInfo/LogError`

### 3. M2 契约最小集 `internal/jsplugin/contract/`
- `meta.go`：Manifest（key/version/models/fetchMode(batch|per_task)/routes[]{method,path,type(submit|query),decode,render}/allowedHosts）+ `Validate()`
- `hooks.go`：出入参 Go 结构 + 校验——`DecodeResult{Kind,Model,RequestBody}`、`BuildRequestResult{URL,Method,Headers,Body}`（Body 自由 JSON）、`ParseSubmitResult{TaskID,TaskData,State}`（TaskID 必填；TaskData/State ≤1MiB 自由 JSON）、`QueryResponse{Items[]{TaskID,Done,TaskData,State,Error{Code,Message}}}`；未知字段拒绝（顶层字段白名单校验）
- DX 最小交付：`contract/v1.d.ts`（TS 类型）、`docs/plugin-api/v1.md`（钩子卡片+时序图，从设计方案 §四 摘编）、golden 插件 `internal/jsplugin/testdata/golden/plugin.js`（suno 式：meta+5 必选钩子+renderTask，兼作模板与 E2E 夹具）

### 4. M1 注册与生命周期 `internal/jsplugin/registry.go`
- `migrations/000031_js_plugin.sql`：`js_plugin_versions` 表（goose 格式，照 000030 幂等风格）→ `make dao` 生成 dao/do/entity（DB 不可达时按生成模板手写外部 dao）
- `Upload(source)`：esbuild 编译 → manifest 校验 → hash → 入库（enabled=false）
- `Activate(key, version)`：冲突预检（路由 method+path、模型名大小写 vs 当前 active 集）→ 实例池初始化 → generation 重建
- `Enable/Disable`：翻状态 → generation 重建；`Bootstrap(ctx)`：启动装载（cmd.go 在 plugin.Bootstrap 之后调用）

### 5. M3 分发器 `internal/jsplugin/router/`
- `generation.go`：不可变快照（路由索引：method→pattern 列表，`:param` 段匹配；pluginsByKey）+ `atomic.Pointer` 发布，读侧无锁
- `dispatcher.go`：启动注册**一条静态组** `s.Group("/pjs", ALL("/*path", dispatch))`，挂 relay 同款六中间件链；匹配 `/pjs/{key}/{native...}` → 查 generation → submit 类：复用 `internal/handler/relay/task.go:207 selectTaskChannel` 的渠道选择（js 渠道 type=43），组 RelayInfo 后进 `relay/handler.HandleTaskSubmit` 流程；query 类：查 `tsk_model_tasks` → `renderTask` 钩子 → `response.Success`

### 6. M4 任务桥 `relay/taskchannel/jsbridge/adaptor.go`
- 实现 13 方法：`Init`（存 info + Settings.PluginKey）；`ValidateRequest`→JS decode；`EstimateBilling`→`{"base":1.0}`；`BuildRequestBody`→JS buildSubmitRequest（descriptor 缓存供 URL/Header/Body 三方法）；`DoRequest`（NewPooledClient）；`DoResponse`→JS parseSubmitResponse；`FetchTask`→从 taskData 解 `platform`("js:{key}")+`task_id` → JS buildQueryRequest → 发上游返回 resp；`ParseTaskResult`→JS parseQueryResponse → items→`TaskInfo`（done→SUCCESS/IN_PROGRESS、error→FAILURE）；`GetModelList/GetChannelName`
- `init()` 注册 `ProviderJSTask`；两处小改：`task_handler.go:176` 附近——ProviderJSTask 时 platform=`"js:"+PluginKey`；`async_polling.go:466` taskData 加 `"platform": task.Platform`

### 7. 管理端 API（API-only）
- `api/admin/v1/jsplugin.go`：GET `/js-plugins`、POST `/js-plugins/upload`、POST `/{key}/versions/{version}/activate`、POST `/{key}/enable|disable`、DELETE `/{key}/versions/{version}`、GET `/{key}/routes`（generation 预览）；`gf gen ctrl -m` + `gf gen service`，logic 转发 registry（照 plugin.go 模式）
- 权限：`predefinedPermissionGroups` 加 `plugin:upload`/`plugin:manage`；`adminPermissionRules` 加 `/api/admin/js-plugins*` 映射（上传/版本→upload，启停/激活/删除→manage）；跑 `rbac_coverage_test` 保通过

### 8. cmd.go 接线
- L185 后 `jsplugin.Bootstrap(ctx)`；L316 附近 `jsplugin.RegisterDispatcher(s)`；defer `jsplugin.Shutdown(ctx)`

## 验证

1. 单测：contract 校验样本集（合法/非法/未知字段拒绝）；engine 并发 `-race`（超时中断、panic 重建、池满）；esbuild golden 快照；jsbridge 全链（httptest mock 上游）
2. **E2E 验收**（`internal/jsplugin/e2e_test.go`，照 `internal/testutil/gfserver.go` + httptest 惯例）：起服务 → 上传+激活 golden 插件 → mock suno 上游 → `POST /pjs/golden/submit/music`（测试 API key，渠道指向 mock）→ 断言响应 renderSubmit + `tsk_model_tasks` 落库（platform=js:golden）→ 手动触发一轮 `pollOnce` → `GET /pjs/golden/fetch/{task_id}` → 断言 renderTask 终态输出
3. 回归：`go build ./... && go vet ./...` + 相关包 `go test ./...`；`make migrate` 验证迁移
