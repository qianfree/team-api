# 表达式计费补齐请求感知能力(请求头/请求体参数/时间条件倍率)

## Context

formula 模式(4e7e637)目前只移植了 new-api 的 usage 侧子集(p/c/ctx/缓存/模态变量 + fixed/u()/数学函数),公式无法感知请求头、请求体参数、时间——这些在 team-api 中散落在正交机制(时段乘数/参数倍率)里,无法在公式内自由组合。目标:对齐 new-api 的 Request Rules 能力,让 **formula 模式的费用完全由表达式决定**,支持 `header()`/`param()`/`has()`/`hour()` 等探针函数、请求规则倍率、命中规则留痕,且预扣/结算/任务结算三口径一致。

相对 new-api 的两处刻意改进:
1. **`param()`/`header()` 参数必须是字符串字面量**(编译期拒绝动态参数,与现有 `u()` 口径一致)→ 可静态提取探测集合,任务路径冻结小 map 而非整个请求体。
2. **时间函数绑定定价时刻 billAt 而非 time.Now()**(预扣取当前时刻,结算取 relayInfo.StartTime,与 time_segments 时段乘数同哲学)→ 跨小时边界请求预扣/结算结果恒一致;new-api 此处会在边界处漂移。

存储形态:沿用 new-api 的「基础公式 × 请求规则」乘法组合,但不引入 `|||` 解析 hack——`PricingBlob` 新增独立键 `formula_rules`,引擎求值时组合为 `(base) * (rules)`。

## 一、引擎层 `internal/logic/billing/formula/`

**新文件 `request.go`**:
- `RequestInput{Headers map[string]string; Params map[string]any}` —— **已解析形态**(probe 结果),formula 包不接触原始 body/JSON 解析
- `RequestRuleTrace{Cond string; Multiplier float64; Matched bool}`(对齐 new-api)

**`formula.go`**:
- `Compiled` 增加 `ParamPaths []string`、`HeaderKeys []string`(AST 提取 param()/header() 字面参数,复用 extractUKeys 的 walker 模式;动态参数编译报错)
- 新增 `requestRulePatcher`(ast.Patch):检测形状严格为 `<探针条件> ? <数字字面量> : 1` 的三目(条件须引用 param/header/hour/minute/weekday/month/day 至少一个),原地改写为 `_trace(ruleIndex, cond, multiplier)`;整型乘数走 `_trace_int`;`_trace`/`_trace_int` 为保留标识符。数值结果不变,仅埋点
- `Run` 签名改为 `(c, env) (float64, []RequestRuleTrace, error)`(埋点命中随结果返回)

**`env.go`**:
- `FormulaInput` 增加 `Request *RequestInput`(nil → 探针取空值)、`EvalAt time.Time`(时间函数基准,零值取 now)
- `Env()` 注入新函数闭包:`header(k)`→`Request.Headers[lower(k)]`(缺省 "")、`param(p)`→`Request.Params[p]`(缺省 nil)、`has(v, s)`→strings.Contains、`hour(tz)/minute(tz)/weekday(tz)/month(tz)/day(tz)`→基于 EvalAt 按时区求值(tz 空或非法回退平台计费时区,与时段定价一致)、`_trace/_trace_int` 闭包写命中标记

**`smoke.go`**:
- `SmokeVectors` 不变(空请求下探针取空值,公式须仍非负);`Compile` 内完成字面量/保留标识符校验
- `Evaluate`:结果增加 `Rules` 字段;`PricingFormulaSample` 的请求字段透传试算

## 二、计费链路 `internal/logic/billing/`

**`pricing.go`**:
- 新增 `resolveFormulaRequest(c *formula.Compiled, headers http.Header, body []byte) *formula.RequestInput`:按 `c.ParamPaths` 用**现有 `lookupPath`**(param_multiplier.go:205,点分路径+`[*]` 通配,路径语法与参数倍率机制统一)解析 body,按 `c.HeaderKeys` 归一化 headers。放在 billing 包避免 formula→billing 导入环
- `computeCost` 增加 `req *formula.RequestInput, billAt time.Time` 参数,formula 分支构造 FormulaInput 时带上(EvalAt=billAt);`CostBreakdown` 增加 `RequestRules []formula.RequestRuleTrace`
- `EstimatePreDeductAmount` 增加 `headers http.Header, body []byte` 参数,formula 分支 resolve 后求值(EvalAt=now)
- `BuildPricingBlob`:`PricingBlob` 增加 `FormulaRules *string json:"formula_rules,omitempty"`;保存时 base 与 rules 各自 SmokeTest,组合式 `(base) * (rules)` 再烟测一次;`validatePricingConfigured` 用组合式

**`settlement.go`**:

**`snapshot.go`**:

**`scheme.go` + `task_billing.go`(任务路径)**:
- 提交时:`taskFormulaInput` 增加 req(从 info.RequestHeaders + 任务 body resolve);`EstimateTaskCost`/`PreDeductTask` 链路透传
