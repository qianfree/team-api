# 用户端无障碍读屏优化方案

> 适用范围：`web/tenant`（租户端）
>
> 目标用户：弱视 / 视障用户，借助读屏软件访问（Windows：NVDA、讲述人；iOS/macOS：VoiceOver；Android：TalkBack）
>
> 方向：**优化页面内容的可识别性，让读屏设备能正确读取与操作**，不自研朗读工具

## 1. 背景与目标

### 1.1 目标

读屏软件的工作方式是把 DOM 转成无障碍树（Accessibility Tree）逐元素朗读。当前租户端的问题是：部分内容读不出来（图标、图表）、部分内容读不对（可点击的卡片）、部分操作做不了（无键盘支持）。本方案目标是：

1. **读得到**：所有信息类内容都有文本替代（图标静音、图表有概要、图片有 alt）。
2. **读得对**：页面结构与语义正确（landmark、标题层级、表格语义、状态消息播报）。
3. **操作得了**：所有交互可纯键盘完成，焦点可见、可预期。

对标 WCAG 2.1 AA 中与读屏直接相关的条款：

| 条款 | 要求 | 现状 |
| --- | --- | --- |
| 1.1.1 非文本内容（A） | 图片/图标有替代文本 | 部分缺失（Icon 组件、验证码、图表） |
| 1.3.1 信息与关系（A） | 结构语义可编程确定 | 部分缺失（移动端卡片列表、字段标签） |
| 2.1.1 键盘可操作（A） | 全部功能键盘可达 | 移动端可点击卡片缺失 |
| 2.4.1 跳过区块（A） | 可跳过重复导航 | 无 skip-link |
| 2.4.7 焦点可见（AA） | 焦点指示清晰 | 全局 focus-visible 覆盖不足 |
| 4.1.2 名称/角色/值（A） | 控件有可访问名称 | 图标按钮大面积缺失 |
| 4.1.3 状态消息（AA） | 异步结果自动播报 | loading/空态无 aria-live |

### 1.2 非目标

- 不做自研 TTS 朗读工具条（页面朗读由用户设备上的读屏软件完成，我们的职责是内容可读）。
- 不做暗色模式、字号缩放设置页（属"无障碍阅读"工具条范畴，如需要另立方案）。
- 不改变现有视觉设计；本方案全部改动对视力正常用户**零视觉差异**（唯一例外见 4.5 焦点样式）。

## 2. 现状盘点

### 2.1 已具备的基础（不重复建设）

- `index.html` 已设 `lang="zh-CN"`；路由已同步 `document.title`（`router/index.ts:45`、`Layout.vue:246`）。
- `Layout.vue` 已用语义标签：`<aside>` 侧栏 + `<nav>` 导航 + `<header>` + `<main>`，页面标题是 `<h1>`（`Layout.vue:388`）。
- 模型广场组件无障碍做得较好，可作为全站改造的参照实现：`ModelCard.vue` 用 `article[role=button] + tabindex=0 + keydown`（含 Enter/Space 处理）、复制按钮带动态 `aria-label`、装饰点 `aria-hidden`；`TokenTrendChart.vue` 切换组有 `role=group` + `aria-pressed`。
- Naive UI 内置组件（按钮、输入框、NDataTable、NModal）自带基础语义和键盘支持；`StatusBadge.vue` 状态靠文本而非仅颜色，达标。
- 图片 alt 覆盖率 8/10（仅 `SlideCaptcha.vue` 两张缺）。

### 2.2 问题清单（按影响分级）

**P0 —— 读屏无法获取信息或无法操作（阻断性）**

| # | 问题 | 位置 | 影响 |
| --- | --- | --- | --- |
| 1 | `Icon.vue` 渲染裸 SVG，无 `aria-hidden` | 全站所有页面 | 读屏逐个尝试朗读图标，干扰正文；焦点可落在 SVG 上 |
| 2 | 无 skip-link，路由切换无焦点管理 | `Layout.vue` | 每次换页读屏用户要听完整个侧栏 20+ 个导航项；页面切换后读屏不知道内容变了 |
| 3 | 移动端卡片列表纯 div，整卡可点击但无 role/tabindex/键盘事件 | `ResponsiveDataTable.vue:181`（`rowClick` 模式） | TalkBack 用户无法得知卡片可点、无法键盘触发 |
| 4 | 图表 canvas 对读屏完全不可见 | `charts/TokenTrendChart.vue`、`charts/ModelDistChart.vue` | 核心用量数据（弱视用户最关心的花费信息）读不出来 |
| 5 | 图标按钮无可访问名称 | 全站（Playground 复制/清空、日志页操作列、表格刷新等） | 读屏只读出"按钮"，不知道干什么 |

**P1 —— 语义与播报缺失（体验性）**

| # | 问题 | 位置 |
| --- | --- | --- |
| 6 | 移动端卡片字段名与值无关联（label 和值是并列的 div） | `ResponsiveDataTable.vue:226` |
| 7 | 表格 loading/空态无 `aria-live`，读屏不播报结果到达 | `ResponsiveDataTable.vue:183-188` |
| 8 | `BaseModal` 关闭后焦点不返回触发元素 | `BaseModal.vue`（依赖 NModal trap-focus，但无焦点归还） |
| 9 | `SlideCaptcha` 两张图片无 alt | `SlideCaptcha.vue` |
| 10 | `TopProgress` 顶部进度条纯装饰未静音 | `TopProgress.vue` |
| 11 | `nav` 无名称、侧栏折叠/移动端菜单按钮无 `aria-expanded` | `Layout.vue` |

**P2 —— 弱视兜底与打磨**

| # | 问题 | 位置 |
| --- | --- | --- |
| 12 | 全局 `:focus-visible` 样式缺失，键盘焦点不明显 | `main.css` |
| 13 | 无 `prefers-reduced-motion` 支持（shimmer/swing/glow 持续动画） | `main.css` |
| 14 | `--text-mute`/`--text-dim` 等文字组合对比度未按 AA（4.5:1）校验；落地页存在 10-11px 小字号 | `LandingPage.vue` 等 |
| 15 | 双重 `<h1>`：Layout 头部一个 + 部分子页面自带一个（Dashboard/Redeem/Wallet 等） | 各页面 |

## 3. 改造原则

1. **原生语义优先，ARIA 打补丁**：能用 `<button>`/`<a>`/`<table>` 就不用 `role` 模拟；ARIA 只用于 div 结构无法替换的场景（如卡片整卡可点）。
2. **改公共组件优先于逐页修改**：`Icon.vue`、`ResponsiveDataTable.vue`、`BaseModal.vue` 一处修复全站生效，页面层只做查漏。
3. **不动 Naive UI 内部**：组件自带语义不重复包裹（不给 NButton 外面再套 role），避免升级冲突。
4. **零视觉回归**：除焦点样式外，所有改动只增属性不改样式。

## 4. 具体方案

### 4.1 布局与导航层（`Layout.vue`、`AuthLayout.vue`、`router/index.ts`）

```html
<!-- ① skip-link：Layout 模板首个元素，Tab 第一站，回车跳到主内容 -->
<a href="#main-content" class="skip-link">跳到主内容</a>
```

```html
<!-- ② landmark 命名 + 主内容锚点 -->
<nav class="sidebar-nav" aria-label="主导航">
<header ...><!-- 保持 -->
<main id="main-content" tabindex="-1" ...>
```

```html
<!-- ③ 折叠/菜单按钮补状态 -->
<button ... :aria-expanded="sidebarCollapsed" :aria-label="sidebarCollapsed ? '展开侧栏' : '收起侧栏'">
```

```ts
// ④ 路由切换焦点管理：router/index.ts 的 afterEach 中（title 同步已有，追加焦点移动）
if (to.path !== from.path) {
  nextTick(() => {
    document.getElementById('main-content')?.focus({ preventScroll: true })
  })
}
```

焦点移到 `<main>` 后，NVDA/VoiceOver 会自动朗读新页面的标题（Layout 的 `<h1>{{ pageTitle }}</h1>`），用户立即知道"我到哪个页面了"。这是读屏用户感知 SPA 路由切换的标准做法。

`AuthLayout.vue` 同步补 skip-link 与 `<main>` 锚点。

`skip-link` 样式加到 `main.css`：默认 `sr-only`，`:focus` 时固定左上角可见。

### 4.2 公共组件层（一处修复，全站生效）

**`Icon.vue` —— 全站图标静音（收益最大的单项改动）**

```html
<svg aria-hidden="true" focusable="false" ... >
```

装饰性图标一律对读屏隐藏；语义信息一律由相邻文字或按钮的 `aria-label` 承担（本仓库图标均为装饰用法，无信息独占场景）。

**`ResponsiveDataTable.vue` —— 移动端卡片读屏化**

参照 `ModelCard.vue` 已验证的实现：

```html
<!-- rowClick 模式下的卡片 -->
<article
  v-if="rowClick"
  role="button" tabindex="0"
  :aria-label="`查看 ${title} 详情`"
  @click="rowClick(row)"
  @keydown.enter.prevent="rowClick(row)"
  @keydown.space.prevent="rowClick(row)"
>
<!-- 无 rowClick 时保持 article，无需 role -->

<!-- 字段名与值关联：div 换 dl 结构 -->
<dl>
  <div>
    <dt class="text-xs text-gray-400">{{ field.title }}</dt>
    <dd>{{ field.value }}</dd>
  </div>
</dl>

<!-- 状态播报 -->
<div v-if="loading" role="status" aria-live="polite">加载中…</div>
<div v-else-if="data.length === 0" role="status">暂无数据</div>
```

桌面端走 NDataTable，原生 `<table>` 语义齐全，无需改动（核对各列 `title` 配置完整即可）。

**`BaseModal.vue` —— 焦点归还**

NModal 的 trap-focus 场景内没问题，但关闭后焦点会落到 `<body>`，读屏用户"迷路"。方案：打开时记录 `document.activeElement`，关闭（含 Esc）后 `nextTick` 归还焦点：

```ts
let lastFocused: HTMLElement | null = null
function onAfterEnter() { lastFocused = document.activeElement as HTMLElement }
function onAfterLeave() { lastFocused?.focus() }
```

**其余小组件**

| 组件 | 改动 |
| --- | --- |
| `BasePagination.vue` | nav `aria-label="分页"`；当前页 `aria-current="page"` |
| `SlideCaptcha.vue` | 两张 img 补 `alt`（"验证码背景图"/"滑块拼图"）；操作结果文字化提示已有则核对 |
| `TopProgress.vue` | 根元素 `aria-hidden="true"`（纯装饰） |
| `StatusBadge.vue` | 已达标，不动 |
| `BaseSelect.vue` / `DateRangePicker.vue` | 核对底层 NPopselect/NDatePicker 是否已带 `aria-expanded`，缺则在触发器上补 |

### 4.3 图表层（`charts/`）

canvas 内容读屏不可见，给容器加 `role="img"` 并用数据动态生成概要：

```html
<div role="img" :aria-label="chartSummary">
  <canvas ... />
</div>
```

```ts
// TokenTrendChart：如 "近 7 天用量趋势：输入 123.4 万 tokens，输出 45.6 万 tokens，10 月 12 日最高"
const chartSummary = computed(() => `近 ${days} 天${metricLabel}趋势：峰值 ${peak}，当前 ${latest}`)
```

数据源已在组件内（图表本身就在渲染它），生成概要零额外请求。趋势的具体数值本就非精确读数（看图也是估读），概要满足"信息等价"。

### 4.4 页面层查漏（逐页扫描，机械性整改）

全站扫描图标按钮模式（`<Icon` 相邻 `@click`、操作列 render 函数里的按钮），统一补 `aria-label` 或可见文字。重点页面：

- `service/`：Playground 各 Tab（复制、清空、下载）、UsageLogs / TaskLogs / RequestAuditLogs 操作列
- `finance/`：Orders、Wallet 操作按钮
- `settings/`：ApiKeys 显示/复制密钥
- `team/`：Members 操作菜单（已有 aria-haspopup ✅，补漏即可）
- `notification/`：NotificationsPage 已读/删除

同时把双 `<h1>` 归一：保留 Layout 头部的 `<h1>{{ pageTitle }}</h1>`，子页面自有 `<h1>` 降级为 `<h2>`（视觉不变，只换标签）。

### 4.5 弱视兜底（顺手项，低成本）

```css
/* main.css 追加 */

/* ① 全局键盘焦点样式：品牌色描边，替代浏览器默认细虚线 */
:focus-visible {
  outline: 2px solid var(--color-primary-500);
  outline-offset: 2px;
  border-radius: 4px;
}

/* ② 减少动效：前庭障碍用户及读屏用户减少干扰 */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}

/* ③ 读屏专用内容（skip-link、图表概要兜底等） */
.sr-only {
  position: absolute; width: 1px; height: 1px;
  padding: 0; margin: -1px; overflow: hidden;
  clip: rect(0 0 0 0); white-space: nowrap; border: 0;
}

/* ④ skip-link 聚焦时可见 */
.skip-link {
  position: fixed; top: 8px; left: 8px; z-index: 100;
  padding: 8px 16px; border-radius: 8px;
  background: var(--color-primary-500); color: #fff;
  transform: translateY(-200%); transition: transform 0.2s;
}
.skip-link:focus { transform: none; }
```

对比度：用工具过一遍 `--text-dim` / `--text-mute` 与各背景组合，不达 4.5:1 的调深一档（如 `#94a3b8 → #64748b` 级别微调）；落地页 10-11px 字号提到 12px。此项允许放 P2，不阻塞读屏目标。

## 5. 实施拆期

| 阶段 | 内容 | 工作量 | 验收 |
| --- | --- | --- | --- |
| **P0 阻断项** | Icon 静音、skip-link + 路由焦点管理、landmark 命名、移动端卡片键盘化、图表概要、SlideCaptcha alt | ~1 天 | NVDA 可完成"登录→导航→看图表→进表格"全流程 |
| **P1 体验项** | 图标按钮全站补标、BaseModal 焦点归还、分页/下拉 aria、字段 dl 关联、loading/空态播报 | ~1-2 天 | 无"无名按钮"；弹窗关闭焦点返回触发器 |
| **P2 打磨项** | focus-visible、reduced-motion、对比度与小字号、h1 归一 | ~1 天 | axe 扫描 0 严重问题；Lighthouse 无障碍 ≥ 90 |

依赖关系：P0/P1 互不依赖可并行；4.2 的 `sr-only` 类需先于图表概要落地的部分场景。

## 6. 验证方式

**静态扫描**

- Chrome DevTools → Elements → Accessibility 面板：抽查关键页无障碍树，landmark/名称齐全
- axe DevTools 扫 `Layout`/`MarketplacePage`/`UsageLogsPage`/`PlaygroundPage`/`DocsPage`：0 critical
- `bun run build`（含 vue-tsc）通过

**读屏实测脚本（NVDA，Windows 本机即可）**

1. 登录页：Tab 第一个焦点是"跳到主内容"；表单标签朗读正确
2. 进入仪表盘：听到页面标题；图表区域朗读"近 7 天用量趋势：…"
3. 侧栏导航：方向键逐项朗读菜单名；进入"用量日志"听到新页面标题
4. 日志表格：NDataTable 表头/单元格逐格朗读；翻页后听到"加载中"→数据播报
5. 图标按钮：聚焦复制按钮朗读"复制模型 ID xxx"；弹窗打开焦点入内、Esc 关闭焦点返回按钮
6. 移动端（TalkBack）：模型广场卡片可单击激活、朗读卡片概要

**防回归（可选）**

- 引入 `eslint-plugin-vuejs-accessibility`，开启 `alt-text`、`aria-props`、`click-events-have-key-events`、`no-autofocus` 四条核心规则，存量告警按 P1 清单消化

## 7. 风险与边界

| 风险 | 应对 |
| --- | --- |
| `Icon.vue` 加 aria-hidden 后个别"信息独占图标"被静音 | 全仓图标均为装饰用法（已核实），若未来出现语义图标，允许单点覆盖 `:aria-hidden="false"` + aria-label |
| 路由焦点管理影响既有 Tab 焦点习惯 | `preventScroll` 避免滚动跳动；仅页面切换时触发，页内不受影响 |
| BaseModal 焦点归还在嵌套弹窗场景行为 | 记录的是"打开时"的 activeElement，嵌套时即上级弹窗内元素，语义正确；实测覆盖 |
| Naive UI 升级带来的语义变化 | 本方案不侵入组件内部；升级后用第 6 节脚本回归 |
