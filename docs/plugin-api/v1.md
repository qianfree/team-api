# JS 任务插件 API v1

面向插件作者的唯一接口规范。配套交付：`internal/jsplugin/contract/v1.d.ts`（TS 类型，IDE 补全）、内置插件 `internal/jsplugin/builtin/golden/plugin.js`（最小模板）与 `builtin/sora-js/plugin.js`（视频生成完整示例：计费/产物转存/配置全量示范）。以 Go 侧 `internal/jsplugin/contract` 为事实源，不一致以代码校验为准。

**内置与上传**：插件分两类来源——内置（go:embed 随二进制，管理端可见标记「内置」，不可删除）与上传（管理端上传 plugin.js）。上传版本激活即覆盖同 key 内置版本，删除上传版本后自动回落内置。分发格式与契约对两类完全一致。

**验收一句话**：照 golden 插件起步，删掉不需要的钩子，上传即被校验——不读基座代码也能写对。

---

## 1. 心智模型：一次任务的完整生命周期

```
客户端 ──── 基座 ──────────────── 插件(JS) ──────── 上游厂商
  │  POST /pjs/{key}/submit/music
  ├─→ 分发器匹配路由 → ① decodeRequest ──→  "这是什么请求？什么模型？"
  │            ←─ {kind:"submit", model, requestBody}
  │  查定价·预扣（基座）
  ├──────────────────────────── ② buildSubmitRequest → "怎么调上游？"
  │            ←─ {url, method, headers, body}
  │  ══ 基座发起上游请求（Authorization 由基座注入渠道密钥）══
  │            ←─ ③ parseSubmitResponse ←─ "受理了吗？任务ID？"
  │            ←─ {taskId, taskData, state}
  │  落库（task_xxx），按 ④ renderSubmit（可选）渲染响应
  │
  │  ⏰ 每轮轮询（基座 15s 循环）：
  │            ←─ ⑤ buildQueryRequest → "怎么查进度？"
  │            ←─ ⑥ parseQueryResponse ←─ "完了吗？"
  │            ←─ {items:[{taskId, done, taskData, state, error?}]}
  │  终态：结算（基座）→ 产物处理（v1 未启用）
  │
  │  GET /pjs/{key}/fetch/:task_id
  ├─→ ⑦ renderTask（可选）→ "给客户端看什么格式？"（缺省=透传任务字段）
```

**必选五钩子**（最小任务插件）：`decodeRequest`、`buildSubmitRequest`、`parseSubmitResponse`、`buildQueryRequest`、`parseQueryResponse`。可选：`renderSubmit`、`renderTask`。

## 2. manifest（`export const meta`）

```js
export const meta = {
  apiVersion: 1,
  key: "golden",                  // 小写字母开头，[a-z0-9-]，2-30
  name: "Golden 示例插件",
  version: "1.0.0",               // semver；同版本号不允许改源码（hash 锁定）
  models: ["golden_music"],       // 接管的平台模型名；跨插件不可重复/仅大小写不同
  fetchMode: "per_task",          // per_task（默认）| batch（同渠道整批一次上游往返）
  allowedHosts: [],               // utils.fetch 额外白名单：host 或 host:port
  usageSchema: [                  // 计费用量单位声明（插件管"用了多少"，基座管"多少钱"）
    { key: "clips", type: "number", unit: "count", description: "生成歌曲段数" },
    { key: "tier",  type: "enum", description: "档位（展示用）" },
  ],
  config: [                       // 插件配置项（管理端动态表单，加密字段掩码存储）
    { key: "api_key", label: "厂商密钥", type: "string", encrypted: true },
    { key: "max_clips", label: "单次上限", type: "int", default: 4, halfWidth: true },
  ],
  routes: [
    { method: "POST", path: "/submit/:action", type: "submit" },
    { method: "GET",  path: "/fetch/:task_id",  type: "query" },
    // dynamic（可选）：一型两用——解码结果定走向（suno 式 POST /fetch 批量查询）
    // { method: "POST", path: "/fetch", type: "dynamic", decode: "decodeBatch" },
  ],
};
```

- 路由实际地址 = `/pjs/{key}` + path；`:param` 段进入钩子的 `ctx.params`；
- 同插件内 `method + 路径形状` 唯一；跨插件形状冲突在激活时被拒绝；
- **v1 仅接受零 import 的单文件插件**（esbuild 编译期拒绝任何 import）；
- `taskData` / `state` / `requestBody` 各限 **1MiB**，超限拒绝（不是截断）。

## 3. 钩子卡片

通用规则：**抛 `Error` = 插件级失败**（基座转为 4xx/502 透出，任务级失败用 `items[].error`）；返回顶层未知字段被拒绝（查拼写）；所有出入参走 JSON 边界。

### ① decodeRequest（必选）｜请求分类归一
- **入参** `{path, method, params?, body?, headers?}`（body 为客户端请求体原文）
- **返回**（二选一）：
  - `{kind:"submit", model, requestBody?}` — model 必须在 `meta.models` 中声明
  - `{kind:"query", taskIds}` — **仅 dynamic 路由**：这是存量任务查询（如 body 里的 ids 列表），分发器改走批量查询渲染（≤100 个）
- **语义**：从原生路径参数/请求体推出模型与归一化请求体；非法请求在此抛错

### ② buildSubmitRequest（必选）｜构造上游提交请求
- **入参** `{body, params?, model, upstreamModel?, channelBaseUrl, state?}`
- **返回** `{url, method?, headers?, body?}`
- **语义**：url 为相对路径（拼到渠道 baseUrl）或绝对 URL（host 须在白名单）；`Authorization` 由基座注入渠道密钥，声明了也会被忽略

### ③ parseSubmitResponse（必选）｜解析受理
- **入参** `{status, responseBody?}`
- **返回** `{taskId, taskData?, state?}` — **taskId 必填**
- **语义**：`taskData` 是上游快照（落库、轮询回带），**每轮被查询结果整体覆盖**；跨轮要存活的数据放 `state`；`state` 省略 = 保持原值
- **immediate**（可选，同步即完成）：`{status:"SUCCESS"|"FAILURE", taskData?, usage?, artifacts?, failReason?}` — 同步图片 API 等提交即出结果的厂商：任务**免轮询直达终态**，结算/产物与轮询终态同口径；usage/artifacts 语义与 parseQueryResponse 终态一致

### ④ buildQueryRequest（必选）｜构造上游查询
- **入参** `{tasks:[{taskId, taskData?, state?}], model?}`（per_task 恒单元素）
- **返回** `{url, method?, headers?, body?}`

### ⑤ parseQueryResponse（必选）｜解析进度
- **入参** `{status, responseBody?, tasks}`（tasks 为 echo）
- **返回** `{items:[{taskId, done, taskData?, state?, usage?, artifacts?, error?}]}`
- **语义**：`done:false` → 进行中；`done:true` → 终态（有 `error:{code,message}` = 失败，否则成功）；items 的 taskId 必须都在本次查询集合内
- **usage**（终态可选）：用量事实 `{clips: 2}`，键必须 ∈ `usageSchema`；number 型进公式 `u()` 通道（unit=second 额外作时长信号）——结算按官方计量多退少补，插件对价格世界一无所知
- **artifacts**（终态可选）：产物声明 `[{key:"audio", source:{type:"url", path:"data.audio_url"}}]`——只指路不碰字节，宿主自动转存对象存储并把 taskData 里的 URL 改写为本地 OSS 链接（失败回落原 URL 自动重试）

### ⑥ renderSubmit / ⑦ renderTask（可选）｜客户端渲染
- **入参** `{task:{publicTaskId, taskId, model, status, progress?, failReason?, data?}}`
- **返回** `{status?, body}`（缺省 status=200）；**不导出则走默认透传**

## 4. 宿主能力 `utils`（全局注入）

```js
utils.fetch({url, method?, headers?, body?, responseType?})  // 同步阻塞；≤4次/钩子、15s/次、30s/批、1MiB/响应
                                                               // 目标 host 须 ∈ 渠道 baseUrl host ∪ meta.allowedHosts；不跟随重定向
utils.log.info/warn/error(message, fields?)                   // 应用日志 + 任务日志（作者排错生命线）
utils.config.get("key")                                       // 读自己的配置（manifest.config 声明；加密字段已解密；未声明键=undefined）
utils.now()                                                   // 毫秒时间戳
utils.uuid()                                                  // UUID v4
utils.crypto.hmacSHA256(message, secret)                      // → hex 小写（new-api 同名同参）
utils.crypto.jwtSignHS256(claims, secret)                     // → HS256 JWT（exp/nbf 由 claims 给定；Kling AK/SK 适用）
utils.crypto.base64 / base64URL / base64URLDecode(s)
```

**FileReference（文件引用）**：submit 路由接受 multipart/form-data——字段名 `body` 为 JSON 请求体原文，其余文本字段并入 body 顶层，文件字段成为引用。decode 的 `ctx.files` 收到 `[{ref, field, filename, mimeType, size}]`（ref 形如 `request_file:image` / `request_file:image#1`）；插件在 buildSubmitRequest 的 body **任意深度**放占位符 `{__fileRef, encoding:"base64"|"dataUrl", mimeType?, maxBytes?}`，宿主发送前用上传字节替换（编码为 base64 或 dataUrl）——**文件字节永不进入 JS**。上限：单文件与内联总量 64MB，占位符 maxBytes 可更严。

**dynamic 路由**：type=dynamic 的路由一型两用——decode 返回 `kind:query` 时按 taskIds 批量查询（渲染钩子缺省 `renderTasks`，入参 `{tasks:[...]}`，未导出则返回默认任务数组）；返回 `kind:submit` 时走标准提交。

**immediate（同步即完成）**：parseSubmitResponse 返回 `immediate` 的任务提交即终态，不走轮询。

**钩子别名（new-api 兼容）**：submit 路由可经 `routes[].decode` 指向任意导出的解码函数（缺省 `decodeRequest`），渲染经 `routes[].render` 指名（submit 响应替换标准输出、query 缺省 `renderTask`）——new-api 插件的指名路由无需改函数名即可迁移。

## 5. 上传与生命周期

| 管理端 API | 权限 | 说明 |
|---|---|---|
| `POST /api/admin/js-plugins/upload` `{source}` | `plugin:upload` | 编译校验+manifest 校验，入库 enabled=false |
| `GET /api/admin/js-plugins` | `plugin:upload` | 按 key 归组的版本列表 |
| `POST /api/admin/js-plugins/{key}/versions/{v}/activate` | `plugin:manage` | 激活版本（冲突预检：路由形状/模型名） |
| `GET /api/admin/js-plugins/{key}/config-schema` | `plugin:upload` | 配置 schema + 当前值（加密掩码） |
| `PUT /api/admin/js-plugins/{key}/config` | `plugin:manage` | 更新配置（加密字段空值/掩码=保持）；即刻生效（generation 重建） |
| `POST /api/admin/js-plugins/{key}/enable` `{enabled}` | `plugin:manage` | 启停；路由随 generation 原子生效 |
| `DELETE /api/admin/js-plugins/{key}/versions/{v}` | `plugin:upload` | 删除版本（激活且启用中拒绝） |
| `GET /api/admin/js-plugins/{key}/routes` | `plugin:upload` | 当前生效路由预览 |
| `GET /api/admin/js-plugins/metrics` | `plugin:upload` | 运行指标（钩子调用/错误/耗时 + 任务/产物统计） |

**渠道绑定**：渠道类型「JS 任务插件」，模型路由（`chn_abilities`）绑定模型 → 渠道；`settings.plugin_key` 可选（缺省按模型自动解析）。

**fetchMode=batch**：轮询循环把同渠道同插件的全部未终态任务**打包成一次** `buildQueryRequest`（`ctx.tasks` 携带整批引用），插件返回的 `items[]` 按上游任务 ID 各自映射终态/用量/产物——**上游未回报的任务请省略对应 item**（返回 done:false 也合法，等价"仍在处理"）。批量上游（如 Suno 的 `/fetch` ids 列表）借此把 N 次轮询收敛为 1 次。

**计费（Phase 2 起）**：模型在管理端配置 formula 定价（公式编辑器），插件的 usageSchema number 型键自动注册为公式 `u()` 变量。提交时 `estimateUsage` 出估算事实（预扣），终态 `items[].usage` 出官方事实（结算多退少补）——例：模型公式 `fixed(0.1) * u("clips")` + 终态 `{clips:2}` → 本次 0.2 本位币。**改定价只改公式，插件零改动。**

## 6. v1 边界（明确不支持的）

流式响应转换、SSE——在后续版本以可选字段增量扩展（破坏性变更升 apiVersion 2）。manifest 的 `author` 兼容字符串与 `{name,url?}` 两种形态，`website`（https）为可选展示字段。
